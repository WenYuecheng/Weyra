## P1 — Recheck permissions after asynchronous approval

`agents/tool_runtime.py`, original `_allowed` final approval block (original lines 143–145), returned the awaited confirmation directly. `_run` then checked cancellation but did not reevaluate permission modes or deny rules. A parent can enter plan mode or add a deny rule while a child waits for approval; an earlier approval then executes a newly forbidden tool.

Executed repro: real `ToolRuntime._allowed`, `confirm` suspended on an `asyncio.Event`, default child and parent modes, shell tool. After entering confirmation, set parent mode to `plan` and ancestor deny rules to an always-true rule, then release confirmation with True. Observed `{'parent_mode': 'plan', 'parent_denies': True, 'allowed': True}`. Reevaluate self and ancestor policy after waiting for the approval lock and after confirmation completes. Root notified and working on fix.

## P2 — Commit projection and context version atomically

`agents/context.py:523–533` and the equivalent final publication block in `compact` separately append `compaction` and `context_version`. Each append independently commits in `SessionStore`. Failure/crash on the latter leaves a new model projection durably published under the old version, despite compaction reporting failure.

Executed repro: initialize real SessionStore against SQLite `:memory:`, append a balanced assistant/tool pair with 10,000-character tool content, initialize ContextManager, and wrap `session.append` to raise OSError only for `context_version`. Run `reduce_large_results`. It raises but observed `{'tool_content_len_after_failed_reduction': 5159, 'version': 0, 'compaction_committed': True, 'context_version': None}`. Wrap both records in one transaction and assign the in-memory version only after successful commit. Apply to both result reduction and summary publication.

## P2 — Preserve incomplete child outcomes

`agents/subagent.py`, `_run` immediately after `summary = await child.run_once(...)`, always calls `_finish(record, "completed", ...)`. However `agents/agent_loop.py:372–377` returns normally with truncated text when stop_reason is `length`/`max_tokens`, recording `turn_end.state="incomplete"`. Thus a truncated delegated task or forked skill is durably delivered to its parent as completed without any unresolved explanation.

Executed memory-only ChildManager repro: supplied a child whose `run_once` records `turn_end.state="incomplete"` and returns truncated text, matching AgentLoop's actual contract. Observed `{'child_turn_state': 'incomplete', 'delivered_state': 'completed'}`. Derive the delivered outcome from the child's terminal state, preserving incomplete as a terminal outcome (including inbox/ACK handling), or report failure with an explicit unresolved truncation reason.

No additional concrete P1/P2 findings established in the inspected budget reservation/settlement and skill publication recovery paths.

## Follow-up review — fixes accepted

Inspected root's three fixes and their added regression tests. All three findings are addressed within scope:

- `ToolRuntime._policy` now computes current context/own-agent/ancestor restrictions and deny rules. `_allowed` reevaluates before approval, after acquiring the approval lock, and after the awaited answer. There is no intervening asynchronous yield between final policy evaluation and handler admission. The regression test checks revocation during confirmation prevents both handler effects and tool-intent persistence.
- Both projection paths now call `_publish_projection`, which places compaction and context-version records in one transaction and updates the in-memory version after commit. The parameterized fault-injection test covers both pruning and summary publication and checks the projection, version, and records roll back.
- ChildManager examines turn_end facts generated by the current invocation and reports failed plus an unresolved reason for incomplete turns. This uses an existing terminal status, so durable inbox acceptance and ACK handling remain compatible. The added test exercises a real child Agent with a scripted length-stop response and verifies the durable pending result.

Root reports 50 passing targeted tests across context, tools, subagents, and model runtime. This follow-up reviewed source and tests; it did not independently rerun that suite. No further concrete P1/P2 issue found in these fixes.
