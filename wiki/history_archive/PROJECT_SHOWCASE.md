# 项目展示口径

**Weyra：统一多厂商、缓存友好上下文与经验辅助技能演化的轻量 Python Agent Harness。**

项目面向本地单用户的项目分析和个性化写作。主任务、子任务、摘要、Memory 选择及技能维护共用模型运行层；工具通过统一权限、调度、检查点与结果提交路径执行，SQLite 保存可恢复的结构化事实。

可用于简历的描述：

- 参考 Pi 的厂商适配和执行循环，在 Python 中实现统一 Provider 注册、用途路由、请求冻结、流式归一化及共享预算，支持 OpenAI-compatible 和 Anthropic 协议。
- 对齐 DSH 固定版本的摘要提示词、压力预算和工具结果剪枝，结合 Hermes 的稳定快照思路，实现可追踪上下文投影、完整尾部、一次 overflow 恢复及真实缓存用量记录；不将前缀稳定直接等同于缓存收益。
- 实现 spawn/fork、有界并发、双输入队列、后台进程和资源所有权，以 SQLite 事务保证输入确认、子结果交付、预算结算及分支恢复，增加撤权、取消和发布失败测试。
- 借鉴 WikiSkill 的经验/知识/技能分离与 SkillOpt 的局部编辑思路，实现经验辅助维护、有界补丁、来源追溯、原子发布恢复与版本回滚。

展示时使用 `weyra demo --scenario analysis|writing --offline`，说明两类任务共用一套运行层。工程测试数量和离线结果引用 [当前证据](verification.json)；真实接入和费用引用 [真实验证记录](live-validation.json)。当前 CUN DeepSeek 文件工具链及二十个基准场景通过；五组专项的原始结果有检查失败与容量错误，详见 [真实效果报告](EFFECTS.md)。GLM/GPT 最小请求失败；不能在简历中写“真实多厂商全部验证”“缓存降低多少”或“写作质量提升多少”。

源码对齐属于机制理解、Python 适配、系统整合与针对性工程改进。完整论文训练未复现；日常自进化默认关闭，显式开启必须配置独立模型评审及宿主验证任务。新旧版本实际执行后，严格要求任务成功数增加、硬约束失败不增加，且顺序交换盲评一致支持候选；平局与异常保留旧版本。当前交付与最终评测范围见 [最终执行清单](FINAL-CAMPAIGN.md)。

最终结果和简历以 [FINAL-REPORT.md](FINAL-REPORT.md) 与 [FINAL-RESUME.md](FINAL-RESUME.md) 为准。正常Agent定位正确／合理弃权26/48→40/48，增加29.2个百分点；新技能三组未发布新版本，不能宣称获得持久更新收益。294个槽位全部形成终态；早期实验和负结果保留，分别统计。
