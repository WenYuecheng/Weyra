# TUI 兼容性、架构与完备性核查

核查日期：2026-10-20。范围：当前 Weyra 工作区，对照原有普通 CLI、Agent 和会话命令；不以界面相似视为完整复现 BearCode、Pi 或 DSH。

## 结论

发现真实兼容性回退并完成本轮修复。全量离线回归未发现剩余测试失败；这不等于所有真实厂商、长期运行和压力场景已经验证。

## 已修复

- 将原 CLI 会话命令提取到 `agents/session_commands.py`，普通 CLI 与应用服务共享原有实现和权限判断；保留公开的 `agents.main.command` 与 `session_path` 入口。
- 恢复 TUI `/tree`、`/branch`、`/fork`；恢复 Memory 写入的 Plan/dontAsk 和忙碌限制，并对会话变更实施应用服务活动检查。
- MCP 信任操作沿用原来的异步处理，不将协程误当完成结果。
- 技能回滚被拒绝时不再返回成功；界面不再把新发布版本误称为历史版本号。
- 修复同一请求 ID 携带不同正文被错误当作重复成功；紧邻提交的第二条提示进入 Steering，避免在 Agent 尚未进入运行状态时启动第二个主任务。
- 会话切换先校验目标存在，拒绝不存在的会话时保留当前实例。
- 命令引号错误返回结构化失败；Memory、历史和树等命令的返回数据实际显示在 TUI，失败不清除草稿。
- 离线 TUI 演示与原普通演示一样关闭自动演化。
- 修正输出查看测试对滚动位置的依赖，使用聚焦后的键盘激活验证完整操作路径。

## 架构判断

展示组件 → 应用服务 → Agent/会话/运行时的主方向清晰。提取共享命令避免维护两套权限和命令语义；未增加数据库、网络层或新的运行循环。

界面仍包含与服务重复的局部展示状态，服务也仍封装部分 Agent 私有状态；不应宣称已经完成所有公共接口抽取。本轮没有为形式统一重写执行内核。
