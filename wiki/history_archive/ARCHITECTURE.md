# 架构

当前技能更新入口增加 `skill_judge` 独立路由及 `[skill_evolution]` 显式开启配置。
普通任务默认不启动技能自进化；开启时必须绑定固定的宿主验证清单或能返回实际产物的回调。
`ConfiguredSkillGate` 对每道验证任务隔离执行新旧技能，检查文件与结构化事实，再由独立模型交换顺序盲评。
`EvolutionStore` 继续执行严格收益、资源漂移和原子发布检查；评审不确定或平局不会修改活动版本。
验证清单对普通文件工具隐藏，验证任务工作区只含输入及待测技能，参考答案留在宿主。
Shell授权仍属于宿主访问边界，并未新增完整系统沙箱。

`weyra.main` 统一分派交互会话与运维命令；`commands` 提供 demo、eval、check-config、sessions、export-session、import-session。`Agent` 负责会话所有权、权限与清理，`agent_loop` 负责执行循环，`model_runtime` 负责规范请求、Provider、fallback 和用量记录。

## 事实与模型视图

`SessionStore` 在 `.weyra/state.db` 中持久化事件、分支关系、内容与子任务收件箱。模型上下文是结构化事实的投影；压缩或工具预览裁剪不会替代原始记录。JSONL 是导入导出格式。Memory、Skills 的可编辑正文为 Markdown，其更新、版本和运行来源进入会话记录。

稳定系统前缀与动态环境事实分离；刷新是显式边界。工具声明和当前投影在请求时冻结，完整的 assistant 工具批次与对应结果保持在同一上下文组内。缓存命中取决于服务端实际返回，不能由前缀稳定直接推断。

## 上下文管理

默认采用 DSH 检查点：压力比例 0.8、预留 H=65536、保留比例 0.16，压缩重试与溢出重试均为 1。默认压缩输出上限等于 H；模型输出能力较小时需显式覆盖。阈值为 `floor(min(C×0.8, C−R−H))`，保留量为 `floor((C−R)×0.16)`，其中 R 是请求实际输出预算。配置不满足容量关系时拒绝。

检查点使用固定英文八节指令和固定前言，参考文本在 `data/upstream/`，由哈希测试保护。默认请求重放保留相同前缀；显式 compression 路由或成对摘要模型覆盖时使用指定模型。跨辅助窗口时，Weyra 扩展按完整交互组分段并分层合并，保存覆盖范围与全部成本；单组仍超限或不能收敛时停止，不静默丢弃历史。`single_json` 与 `three_parallel` 是实验模式，三层 JSON 不代表 DSH 默认。缺少兼容服务端 token 测量时，Weyra 使用 UTF-8 字节数除以 2 估算，区别于 DSH 字符数除以 4；金额预留使用完整容量，不依赖此启发式。兼容的正值服务端 usage 可向上或向下校准压力；新增内容继续按保守启发式计入，压缩后负差值在原估计过高时按观测比例折算，防止过量扣减。零值、缺失或不兼容 usage 不用于锚定。

## 工具、任务与知识

只读工具池并发 10；模型瞬态故障最多额外重试两次，这是 Weyra 的低成本工程差异。Pi 风格预览采用 read 头部、shell 尾部各 2000 行/51200 UTF-8 字节，grep 100 条/每条 500 字符/51200 字节。压力清理采用 DSH 的超过 8192 码点时保留头 4096、尾 1024 及固定标记。

子任务默认并发 3、深度 1，spawn 使用独立任务上下文，fork 继承已完成边界的上下文。Goal 默认最多续行 3 次、连续无进展 2 次停止。Memory 检索最多 5 条，选择最多等待 8 秒，每条注入 4 KiB、总量 60 KiB。技能局部补丁最多 2 处，每处 1000 字符；经验最多 10 条、每条 300 字符、注入 2000 字符。这些是 Weyra 工程限制，不是上游默认。

模型调用共享根预算；子任务和辅助调用也计费。调用前预留、调用后结算，未知用量不能伪记为零。MCP 配置仅引用环境变量，信任与工具权限由运行时处理。

维护模型使用固定 JSON 协议示例，与有界补丁接口共享字段约定。每次提案在验证前保存为内容寻址的全文产物，并由 `skill_proposal` 事实记录事件 ID、引用和哈希；拒绝提案也可追溯。该检查点失败则停止发布。维护响应必须完整结束且不带工具调用，不能只凭截断结果中偶然可解析的 JSON 修改文件。


## 后端收尾补充

压缩使用单次事务共享物理调用预算（上限8次，覆盖分段、合并和网络重试），三路组件严格按各自非空对象解析。连续两次失败停止当前轮次自动摘要；免费工具结果剪枝仍可执行，新轮次或手动压缩重置。失败阶段、原因、调用和usage进入SQLite事实记录。

技能定位利用显式ID、反馈关联轮次的成功使用记录、名称/别名及词法候选；歧义弃权，不默认修改首候选。候选在隔离工作区与旧版分别生成验证任务，成功数严格增加且硬约束失败不增加才正式发布。执行技能与维护经验仍隔离。

本轮正式实验通过独立100元根账本记录全部维护、验证、执行及失败费用；正常Agent实际读取输入和写产物，标准答案与评分器不进入模型工作区。终端界面未改动，实验不代替多厂商原生验收或完整论文复现。
