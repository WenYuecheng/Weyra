修复率的分子是每组首轮失败、第二轮通过的题数，分母是该组所有已判定的首轮失败。两组各自延续自己的首轮代码，所以待修题集可以不同。首轮和最终通过数各自使用双方都获得判定的题。该子集有 8 道题因传输故障缺少最终配对判定。五种语言是从 Aider Polyglot 完整题库选取的报告范围。该子集的双侧精确 McNemar 检验 p = 0.119。

## 协议和复算

两组使用 GLM-5.3-Flash、`high` 推理、8,192 输出 token 上限和 `write_file`，每次提交最多发一次模型请求，最多两次正式提交。两组共享题目、Docker 验收和有界测试反馈。Weyra 首轮增加示例、边界和接口检查，修复时用题面、当前代码、变更处的原始模板和最新诊断重建上下文。基线在修复时保留连续会话历史。比较覆盖两套完整执行流程。

- [results.csv](results.csv) 包含五种语言的 176 个任务 ID 和两组各阶段的判定。空字段表示该阶段未取得判定，`infrastructure_error` 表示最终判定缺失。
- [protocol.json](protocol.json) 记录数据集和运行时代码版本、模型参数、并发和冻结记录的 SHA-256。
- [policy.py](policy.py) 是该轮实际采用的提示构造源码。[report.py](report.py) 按逐题判定离线重算配对通过数、修复率分子与分母、胜负及精确配对检验。

```bash
python benchmarks/polyglot/report.py
```

复算只需 Python 3.11+。重算以已取得的验收判定为输入。题目来源和原始模板见 [Aider Polyglot Benchmark](https://github.com/Aider-AI/polyglot-benchmark/tree/7e0611e77b54e2dea774cdc0aa00cf9f7ed6144f)。
