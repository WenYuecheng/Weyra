# 有界回放与技能演进

Weyra 从原问题、原回答和下一轮明确反馈中维护技能。原问题用于开发和修复检查；发布收益只来自独立验证。固定验证集可以保留，但不能把原题修复当成泛化改善。

## 来源与参数

| 来源 | 本轮采用的机制 |
| --- | --- |
| [AutoSkill v2](https://arxiv.org/abs/2603.01145v2) | 从近期用户经验维护可复用技能及其来源 |
| [AutoSkill 官方 SkillEvo](https://github.com/ECNU-ICALK/AutoSkill/blob/main/SkillEvo/README.md) | 冻结真实回放、开发与晋升验证分离、固定候选预算、证据不足时孵化 |
| [SkillOpt 算法 1](https://arxiv.org/html/2605.23904v1#A3.SS1) | 有界补丁、验证严格改善才接受、按技能身份缓存验证 |
| [WikiSkill](https://arxiv.org/html/2608.27454v1#S3.SS2.SSS4) | 经验和技能分离、拒绝候选后保留知识、当前验证满分时停止优化 |
| 原 BearCode | 原问题—回答—后续反馈窗口、来源记录与版本管理 |

**最多 1 个候选、2 个开发样本加 2 个验证样本，是 Weyra 的工程默认值，不是论文原始参数。** 沿用既有异步维护入口、知识注入配额及 DeepAgent 记忆折叠，不增加需求提取或出题模型。

## 在线流程

1. 在提案前冻结本轮样本、角色、验收规则和窗口版本。本轮原任务固定为开发样本；宿主清单可再提供一个开发样本和最多两个独立验证样本。相同任务和交互来源去重，验证正文不交给维护模型。
2. 现有维护调用最多提出一个候选，最多两处编辑，每处旧片段及新增文本不超过 1000 字符。先检查补丁合法性、资源和基线哈希。
3. 在临时目录回放旧版与候选；命中缓存的输出和硬检查不重跑。任何执行硬失败立即结束本次验证。
4. 将最多四例合并成两次裁判请求，交换匿名 A/B 次序并逐例核对。次序不一致时弃权。
5. 独立验证通过数必须严格增加，所有覆盖样本不得新增硬失败、丢失已通过项或降低裁判评分。开发结果单列，不计入发布增益。原子发布前再次核对正文和资源哈希。

提案、试跑、裁判和重试共用一个维护 token 范围及总费用账本；不为每个样本重新分配额度。未显式设置维护范围时使用 20,000 token 上限。失败不生成第二候选。缺少独立验证或输入无法还原时，记录 `incubating`、原因、候选和有界知识，保留旧版本。缓存显示当前独立验证已满分时，在提案之前停止；覆盖新需求须更换窗口并重建基线。

历史证据和版本继续审计保存，**不会自动进入必须重跑的回归库**。在线仅读取当前活动窗口，缓存最多 64 项、2 MB。缓存身份包含技能正文及资源哈希、样本和规则、实际模型配置及备用参数、提供商实现及去除凭据的端点、执行器版本；窗口或配置变化不会沿用旧分数。

## 可回放范围

支持带明确验收规则的纯文本，以及通过文件工具读取、创建或编辑的 UTF-8 文件。记录文件首次访问时的修改前内容和新文件原本不存在的事实；已有输入默认受保护，声明可写的输入才允许修改。实际项目系统指令及有界对话、记忆和子任务事实进入回放身份。

当前输入快照最多 8 个文件、每个 64 KiB、总计 128 KiB；对话最多 8 条、8,000 字符，系统指令最多 16,000 字符。输出每项最多 64 KiB、合计 128 KiB；二进制、过大或不能完整观察的输出直接失败，不静默截断。

代码执行、联网、外部应用、fork 技能以及无法完整还原的输入不自动验证或发布。目录列举和搜索所依赖的目录全集尚未被快照，因此也标记证据不足；仍可保留经验和候选。后台回放只开放有限文件和技能工具，关闭记忆检索、在线演进、MCP 和 Shell。

## 配置与回调

自动演进默认关闭。需显式配置 `routes.skill_judge`、费率和验证清单，再启用 `[skill_evolution].enabled`。裁判不能隐式继承主模型或切换备用路由。清单样例：

```json
{
  "cases": [
    {
      "id": "independent-summary",
      "split": "validation",
      "prompt": "概括给定材料，并标注不确定信息。",
      "files": {},
      "output_mode": "text",
      "rubric": "结论有材料依据；不虚构；明确不确定性。"
    }
  ]
}
```

宿主应提供独立于本次反馈的真实交互或验证清单。清单默认角色为验证，开发使用 `development` / `mutate_dev`，晋升验证也支持 `promotion_test`。纯文本需显式 `output_mode: text` 和非空 `rubric`；文件任务可声明 `hard_constraints.writable_input_paths` 等现有检查规则。

固定清单和自定义回调仍可使用。在线回调须通过 `validation_cases` 提供宿主验收清单，由有界原生门禁执行；在线不再调用可自行发起额外任务的旧回调函数。直接调用门禁的 `__call__` 保留显式全清单及原自定义回调评测行为，不扩大在线窗口。配置入口见[配置参考](CONFIGURATION_REFERENCE.md)。

## 记录、恢复与实验

技能正文与版本在 `.weyra/skills/` 管理；证据、候选、逐例报告、知识与决定保存在 `.weyra/skill-evolution/`。验证报告包含窗口版本、开发/验证角色、缓存命中及实际输出，发布记录指向真实技能版本。回滚创建新的单调版本，保留历史：

```text
/skills
/skill-history <name>
/skill-rollback <name> <version>
```

本地离线流程：`weyra demo --scenario writing --offline --project /tmp/weyra-writing`。固定清单的完整评测可显式调用 `ConfiguredSkillGate.__call__`；在线更新仍只使用冻结的 2+2 窗口。纯文本、文件修改、缓存失效、数据分离及实际发布版本由本仓库回归测试覆盖。

2026-10-28：真实模型效果评测已按用户要求暂停。后续最小接口测试没有获得可靠的结构化输出，不能据此报告技能适应性或泛化收益。旧技能、直接反馈、实际发布技能三组共 72 次计划执行留待后续，本轮没有新的真实任务成绩。

本地研究脚本及其暂停标记保存在未发布的研究工作区；本次运行时发布延续仓库对历史评测代码的清理，不恢复旧的 benchmark 兼容入口，也不发布凭据、会话或私有运行日志。真实效果试验恢复前，应重新确认有效接口、计价和剩余预算，并把结果作为新的证据记录，保留既有历史成绩。工程测试及离线示例可在此期间继续运行。

本轮后端发布在远端最新源码上验证：457 项测试、5 个子测试通过，静态检查与 wheel/sdist 构建通过，13 项独立环境安装和离线命令检查通过。CI 使用单个 Ubuntu/Python 3.11 环境。以上是工程验证，不代表真实模型效果或泛化收益。
