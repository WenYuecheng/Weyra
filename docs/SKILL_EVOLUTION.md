# 验证驱动的技能演进

Weyra 将用户纠偏转化为可积累的知识，再把需要改变执行方法的部分表示为局部技能补丁。核心目标是让技能更新有清晰的归因、验证依据与版本记录。

## 经验、知识与技能

参考 [WikiSkill（2026）](https://arxiv.org/abs/2608.27454)，执行经验、持久知识与可执行技能承担不同职责：经验记录发生了什么，知识沉淀何时适用，技能描述如何执行。

`skills.py` 负责技能快照与定位，`online_skill_evolution.py` 从反馈中生成维护建议，`skill_evolution.py` 管理知识、补丁与版本。微经验的条目与注入配额约束上下文尺寸。

## 有界更新

参考 [SkillOpt（2026）](https://arxiv.org/abs/2605.23904) 的有界文本优化，Weyra 限制局部编辑数量和文本大小，并以原内容匹配与哈希校验绑定基线。当前实现处理技能文档的文本补丁，不是 Python AST 重写器。

维护流程依据已定位技能及使用记录选择更新目标；基线不匹配、收益不足、证据不完整时记录拒绝原因。

## 重执行与裁判

候选技能与旧技能分别在临时工作目录运行固定用例。验证 Agent 仅开放有限文件和技能工具，关闭长期记忆及在线演进。硬断言检查输入保留、所需产物、结构与任务完成状态。

独立 `skill_judge` 路由匿名比较两个结果，分别提交 A/B 与 B/A。对调后结论不一致时弃权；该机制用于降低位置偏好对发布决定的影响。裁判路由必须显式配置，不能隐式继承或自动切换备用模型。

发布要求验证成功数改善、硬断言失败不增加，并通过裁判比较。这里的“不退化”针对固定验证清单中的检查结果，后续任务仍按实际结果检验。

## 版本与恢复

技能正文、版本快照和演进记录在 `.weyra/skills/` 与 `.weyra/skill-evolution/` 中管理。预备发布记录、内容哈希和原子文件替换协同恢复；回滚会发布新的单调版本，保留已发生的历史。

```text
/skills
/skill-history <name>
/skill-rollback <name> <version>
```

## 启用

自动演进默认关闭。配置显式裁判路由、计价和固定验证清单后，将 `[skill_evolution].enabled` 设为 `true`。写入还受当前权限模式约束。

验证清单按 `weyra/skill_judge.py` 的加载器校验，配置入口见[配置参考](CONFIGURATION_REFERENCE.md)。可运行的本地流程示例：

```bash
weyra demo --scenario writing --offline --project /tmp/weyra-writing
```

技能定位配对结果见[工程评测](BENCHMARKS.md)；定位指标用于说明选择能力，候选质量由对应任务与发布门禁评估。
