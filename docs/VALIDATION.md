# 验证与效果实验

## 离线工程验证

运行 `python -m pytest -q` 检查消息与请求快照、供应商流解析、缓存用量口径、预算、权限和副作用、读写屏障、取消、JSONL 恢复、压缩、子任务及技能演化。

测试包含故障注入：流中断、持久化失败、旧版本补丁、重复输入、取消与完成交错、父权限收窄、MCP 超时及进程清理。它们验证确定性行为，不衡量自然语言任务质量。

运行两套 examples 脚本展示实际工具和存储链路。`scenarios.json` 固定二十个后续检查场景，每类十个；清单本身不是已运行的效果实验。

## 小规模真实对照

复用已有服务和凭据引用。先为一个厂商验证一条短链路，限制总调用和总 token；再按实际需要验证其他厂商。不要默认启动全量 benchmark。输入、模型、工具、预算和版本一并记录。

| 专项 | 对照 | 记录 |
|---|---|---|
| 缓存 | 动态基线 / 稳定基线 | 实际缓存读取/写入、输入量、首字延迟；字段缺失标未知 |
| 压缩 | 普通摘要 / 三层摘要加完整尾部 | 约束保留、任务完成、摘要与辅助成本 |
| 子任务 | 单实例 / spawn / fork | 任务质量、父上下文增长、全树用量和时间 |
| Memory | 无召回 / 中文词法 / 模型选择 | 相关率、误注入、首答遵循和超时 |
| 演化 | 全文维护基线 / 经验辅助补丁 | 纠正吸收、跨场景误用、正文增长和维护成本 |

失败保留在固定分母。用于提案的经验、开发对照和最终检查分开；最终检查不能进入候选改写。结构要求用程序验证，主观写作质量采用隐藏版本身份的人工配对复核。

发布缓存命中率前必须有真实厂商字段；发布提升比例前必须有本项目真实对照。当前仓库不包含伪造的模型效果、收费金额或论文复现成绩。
